## 2つのページ

| URL | 中身 | 目的 |
|---|---|---|
| `/` | 決算書PDF 読み取り検証ハーネス | 精度の測定専用。何百件でも一括投入してCSVで集計する |
| `/credit-pro/` | **サービス本体（与信判断検討書 Pro）** | 実際に売るページ。判定・手入力補完・Square決済が入っている |

> **改修の成果は `/credit-pro/` にあります。**
> ルート（`/`）はハーネスで、`harness.js` という別のプログラムが動いています。
> ルートを開いても、手入力欄や決済ボタンは出ません。

## ファイル構成

```
（ルート直下）
├ index.html            ハーネスの画面
├ harness.js            ハーネス専用のプログラム
├ engine.js             判定エンジン（6軸100点）
├ pdf-extract.js        決算書PDFの読み取り
├ xlsx-export.js        Excel生成
├ vendor/               pdf.js・ExcelJS
├ .nojekyll             GitHub Pages 用
└ credit-pro/           ★サービス本体
   ├ index.html
   ├ app.js             画面と各モジュールの接続
   ├ engine.js          ┐
   ├ pdf-extract.js     │ ルートと同一内容。
   ├ xlsx-export.js     ┘ 片方だけ直すとズレるので必ず両方に反映する
   ├ license.js         決済確認（★PAY_URL をここに貼る）
   ├ assets/            Excel見本の画像5枚
   └ vendor/
      └ cmaps/          文字コード変換表（有価証券報告書を読むのに必須）
```

**`engine.js` `pdf-extract.js` `xlsx-export.js` を直したときは、ルートと `credit-pro/` の
両方を同じ内容にしてください。** 片方だけだと、ハーネスの測定結果と本体の挙動がズレます。

`cmaps` は `credit-pro/vendor/` の1か所だけに置き、ハーネスもそこを参照しています。
2か所に置くとファイル数が倍になり、Webアップロードの上限に当たるためです。

## 決済を有効にする（残り3手順）

### 1. Worker の `ALLOW_ORIGIN` を、今テストしているURLに変更する

**ここを変えないと、500円払ってもロックが外れません。** CORSで弾かれるためです。

```
テスト中 : https://<ユーザー名>.github.io
本番移植後: https://kazumono.com
```

変更したら**デプロイを押す**こと（押さないと反映されません）。

### 2. Worker のコードを最新版に差し替えてデプロイ

`/debug` 削除済み・`PRODUCTS` に `500: "yoshin-pro"` 追加済み・`/verify` に `no-store` の版です。

### 3. Square で500円の支払いリンクを作り、`credit-pro/license.js` に貼る

```js
const PAY_URL = "https://square.link/u/XXXXXXXX";   // ← ここだけ書き換える
```

作成時の設定：

- 金額 **500円**
- Frequency **One-time**（Monthly にすると定期課金になります）
- Redirect to a website after checkout: **ON**
- リダイレクト先は、**今そのページを公開しているURL**
  - テスト中　: `https://<ユーザー名>.github.io/<リポジトリ名>/credit-pro/`
  - 本番移植後: `https://kazumono.com/credit-pro/`

未設定（`XXXXXXXX` のまま）の場合、購入ボタンを押すと画面にその旨が表示され、
Square へは遷移しません。原因の切り分けができるようにするためです。

## 動作確認の順番

上から順に、**通らなければ先へ進まない**でください。

1. `/credit-pro/` が表示され、最下部に「ビルド v6」がある（真っ白なら F12 → Console の赤い文字を見る）
2. 決算書PDFを1件置く → バナーと数値の表が出る
3. 足りない項目が「ここだけ入力してください」に出る／入力欄の枠が赤くなる
4. 手入力欄を上から埋めて「この内容で判定する」→ 信用程度A〜Eが出る
5. 同じ会社の別の期を追加で置く → 決算期が自動で並ぶ
6. 別会社のPDFを混ぜる → 赤い警告が出て、判定ボタンが押せなくなる
7. 決済 → 戻ってくる → Excel がダウンロードされ、開ける

**7 が通って初めて、kazumono.com へ移植できる状態です。**

## 読み取りの対象と対象外

- **対応**：計算書類・有価証券報告書・決算短信。千円／百万円などの単位は自動で判別し、百万円に換算します
- **銀行・保険会社**：対象外です。貸借対照表に流動／固定の区分が無く、損益計算書も売上高ではなく経常収益で構成されるため、判定モデルに載りません。検知して画面に理由を表示します
- **スキャンした画像のPDF**：文字が入っていないため読めません。手入力へ誘導します

有価証券報告書は、文字コードの変換表（`cmaps`）が無いと1文字も取り出せないものが多くあります。
**`credit-pro/vendor/cmaps/` を消さないでください。** 消すと、読めていたPDFが
「文字を取り出せませんでした」と表示されるようになり、原因が非常に分かりにくくなります。

## 送信されません

PDFの解析もExcelの作成も、すべてブラウザの中で完結します。

ファイルがサーバーへ送られることはありません。
